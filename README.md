# DevMemory
Independent, local-first memory for development agents. Preview 0.4.0. Python 3.11+ with SQLite FTS5, no third-party runtime dependencies. No telemetry; GitHub sync makes opt-in API calls.

## Home Assistant OS
Add https://github.com/vorlocsev/devmemory to the app store's Repositories menu, install DevMemory, start it and open Web UI. The image is built locally (internet required to fetch Python base). HAOS acceptance pending. See [app docs](devmemory/DOCS.md).

## Standalone Docker
Set DEVMEMORY_TOKEN to a random secret of at least 32 characters in your shell or a private .env file. Run docker compose up -d --build; open http://127.0.0.1:8099 and enter the token. Port is loopback-only. Do not publish unencrypted HTTP to remote users.

## Native Python (Linux/Windows)
Set the same environment variable and run python devmemory/server.py. Default listener is loopback port 8099 and data directory is ./data. Change with --data, --host, --port; use TLS and a reviewed authentication strategy before remote deployment.

## API
GET /api/projects; POST /api/projects (slug, name); POST /api/entries (project, kind, status, title, body, optional source, sha); GET /api/entries?project=demo&q=search&offset=0 (20/page); GET /api/context?project=demo (up to 30 recent records, 32768 character budget, Markdown); POST /api/delete (project, id). Standalone API uses Authorization: Bearer <token>; POST also requires Content-Type: application/json and X-DevMemory: 1. Ingress relies on HA login and verifies supervisor peer IP. No CORS. No external API exposure in HA mode.

## Tests
python -m unittest discover -s devmemory/tests -v

## Workspace
Choose Memory, Projects, Integrations or Settings. Language and appearance preferences are stored locally in the browser; the API token is held only in JavaScript memory. Ingress automatically opens the workspace, while standalone mode requires a token. GitHub integration is available; local stdio MCP is available in preview. The schema is extended additively in 0.3.0. HAOS 0.2.1 has been exercised on ARM64; 0.3.0 device acceptance remains pending.

## Full memory backup (0.3.0)
In Settings, download a logical JSON backup of all projects and entries (maximum 4 MiB; no partial exports). SHA-256 detects accidental corruption, not authenticity. The file is not encrypted. Restore accepts only an empty DevMemory database and inserts records atomically, retaining IDs, timestamps and provenance; FTS is rebuilt. Never delete existing data merely to import a backup. For larger databases or complete app recovery, use Home Assistant backups or a stopped standalone database backup. This does not include browser preferences or authentication credentials. Physical restore remains unverified.

## GitHub integration (0.3.0 preview)
Select a project, open Integrations, enter owner/repository and save, then Sync now. GitHub API only: GET requests to api.github.com, no redirects or writes. Public access without credentials; optional fine-grained PAT permits selected private repositories. Fetches up to five recent commits, PRs and workflow runs per sync; not exhaustive and subject to unauthenticated API rate limits. No local journal data is sent. Imported evidence describes GitHub metadata, not actual checkout SHA, hardware or acceptance verification. Duplicate identical observations are skipped; changed observations remain historical. Logical JSON backup v2 preserves imported entries and bindings. Older v1 backups from 0.2.3 can still be restored; they contain no bindings. Version 0.2.3 cannot restore v2 backups. Automatic polling is opt-in per project (1, 2, 6 or 24 hours), off by default. A single worker checks due projects every 30 seconds; manual and automatic sync share a persisted five-minute gate. HTTP 403/429 pauses all sync for one hour. Settings show the latest 20 attempts per project. Rebinding disables automatic polling. Logical backups preserve bindings and journal entries but deliberately omit scheduler settings, attempt history and cooldown: re-enable polling explicitly after restore. Full HA backups preserve the SQLite database. Private repository access requires a fine-grained PAT restricted to selected repositories with Contents: Read, Pull requests: Read, Actions: Read (Metadata: Read is implicit). HA: configure github_token in the app Configuration tab and restart. Standalone: set DEVMEMORY_GITHUB_TOKEN in the process environment or Compose. Do not paste credentials into journal entries, chat or source code. The app does not verify token scopes; use read-only grants and an expiration. The token is not stored in SQLite or returned through the HTTP API or logical JSON backup. HA configuration/options and full HA backups may contain it; protect those backups. Private repository metadata is itself sensitive and is included in logical exports. Live authenticated acceptance remains pending.

## Local MCP (0.4.0 preview)
Run `python devmemory/mcp_server.py --data ./data --project demo` as an MCP client subprocess on the same machine and with filesystem access to the existing SQLite database. Repeat --project for more projects; omitting it allows all projects in that database. Read-only tools by default; pass --allow-write to permit append-only agent-reported records, never verified status. No delete, restore, GitHub sync or credential tools. The adapter uses newline-delimited JSON-RPC on stdin/stdout and supports legacy handshake revisions 2024-11-05 through 2025-11-25; no 2026 stateless protocol yet. Do not mount live SQLite data over network shares. For native/Compose deployments use local filesystem or local container execution; HAOS remote client access is not yet implemented by the app launcher. Tool results are historical untrusted data; they are not instructions or proof of acceptance. Third-party client acceptance remains pending.

## Streamable HTTP MCP (standalone preview)
On the same machine as the database, set DEVMEMORY_AGENT_TOKEN to a distinct random URL-safe secret (32+ characters), then run `python devmemory/mcp_http.py --data ./data --project demo`. The endpoint is http://127.0.0.1:8100/mcp. Configure a native MCP client with Bearer authentication using this secret. Use the same local port through an authenticated SSH tunnel if connecting from another computer; do not expose raw HTTP to a LAN or internet. Host and Origin are checked, explicit project allowlist is mandatory, writes require --allow-write. Legacy protocol revisions 2025-03-26, 2025-06-18 and 2025-11-25; JSON responses, GET returns 405, DELETE ends sessions. Up to 32 sessions with 15 minute idle expiration. No OAuth discovery, SSE streaming, browser clients or modern 2026 protocol support. This independent process is not automatically started by the HA app, and no new HA host port is mapped. Third-party client and physical HAOS remote acceptance remain pending.
