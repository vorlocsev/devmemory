# DevMemory 0.4.2 (preview)
After installation, Start → Open Web UI. The web UI is administrator-only via Home Assistant Ingress; no host port, Supervisor API or hardware privileges are requested. Data lives in /data/memory.sqlite3. Include the app in Home Assistant backups; for a manual file copy, stop the app first (SQLite WAL). Test restore before relying on backups. Export context includes up to 30 newest entries with a 32,768-character budget; oversized output is marked as limited. It is not a full backup. The preview permits up to eight concurrent requests and lists 20 records per page. Resource targets have not yet been measured on a Raspberry Pi.

Create a project in Projects. Optionally enter owner/repository and choose an automatic sync interval (off by default); creation, binding and schedule are saved in one transaction. Invalid input or duplicate IDs leave existing data unchanged. No immediate API request is made; use Sync now in Integrations if desired. MCP project access must still be configured separately. Add entries, choose a kind and evidence status, then search within that project. Verified evidence requires a source and exact SHA; this checks fields, not source authenticity. Never store tokens or secrets. Delete removes a record from active search, not historical backups or forensic remnants.

Remote MCP and semantic search are not implemented. GitHub synchronization is implemented in preview. Do not expose the standalone HTTP service to the internet. This preview has not yet been installed on HAOS.

## Workspace
Choose Memory, Projects, Integrations or Settings. Language and appearance preferences are stored locally in the browser; the API token is held only in JavaScript memory. Ingress automatically opens the workspace, while standalone mode requires a token. GitHub integration is available; local stdio MCP is available in preview. The schema is extended additively in 0.3.0. HAOS 0.2.1 has been exercised on ARM64; 0.3.0 device acceptance remains pending.

## Full memory backup (0.3.0)
In Settings, download a logical JSON backup of all projects and entries (maximum 4 MiB; no partial exports). SHA-256 detects accidental corruption, not authenticity. The file is not encrypted. Restore accepts only an empty DevMemory database and inserts records atomically, retaining IDs, timestamps and provenance; FTS is rebuilt. Never delete existing data merely to import a backup. For larger databases or complete app recovery, use Home Assistant backups or a stopped standalone database backup. This does not include browser preferences or authentication credentials. Physical restore remains unverified.

## GitHub integration (0.3.0 preview)
Select a project, open Integrations, enter owner/repository and save, then Sync now. GitHub API only: GET requests to api.github.com, no redirects or writes. Public access without credentials; optional fine-grained PAT permits selected private repositories. Fetches up to five recent commits, PRs and workflow runs per sync; not exhaustive and subject to unauthenticated API rate limits. No local journal data is sent. Imported evidence describes GitHub metadata, not actual checkout SHA, hardware or acceptance verification. Duplicate identical observations are skipped; changed observations remain historical. Logical JSON backup v2 preserves imported entries and bindings. Older v1 backups from 0.2.3 can still be restored; they contain no bindings. Version 0.2.3 cannot restore v2 backups. Automatic polling is opt-in per project (1, 2, 6 or 24 hours), off by default. A single worker checks due projects every 30 seconds; manual and automatic sync share a persisted five-minute gate. HTTP 403/429 pauses all sync for one hour. Settings show the latest 20 attempts per project. Rebinding disables automatic polling. Logical backups preserve bindings and journal entries but deliberately omit scheduler settings, attempt history and cooldown: re-enable polling explicitly after restore. Full HA backups preserve the SQLite database. Private repository access requires a fine-grained PAT restricted to selected repositories with Contents: Read, Pull requests: Read, Actions: Read (Metadata: Read is implicit). HA: configure github_token in the app Configuration tab and restart. Standalone: set DEVMEMORY_GITHUB_TOKEN in the process environment or Compose. Do not paste credentials into journal entries, chat or source code. The app does not verify token scopes; use read-only grants and an expiration. The token is not stored in SQLite or returned through the HTTP API or logical JSON backup. HA configuration/options and full HA backups may contain it; protect those backups. Private repository metadata is itself sensitive and is included in logical exports. Live authenticated acceptance remains pending.

## Local MCP (0.4.2 preview)
Run `python devmemory/mcp_server.py --data ./data --project demo` as an MCP client subprocess on the same machine and with filesystem access to the existing SQLite database. Repeat --project for more projects; omitting it allows all projects in that database. Read-only tools by default; pass --allow-write to permit append-only agent-reported records, never verified status. No delete, restore, GitHub sync or credential tools. The adapter uses newline-delimited JSON-RPC on stdin/stdout and supports legacy handshake revisions 2024-11-05 through 2025-11-25; no 2026 stateless protocol yet. Do not mount live SQLite data over network shares. For native/Compose deployments use local filesystem or local container execution; HAOS remote access is available as an opt-in managed HTTPS service (physical acceptance pending). Tool results are historical untrusted data; they are not instructions or proof of acceptance. Third-party client acceptance remains pending.

## Streamable HTTP MCP (standalone preview)
On the same machine as the database, set DEVMEMORY_AGENT_TOKEN to a distinct random URL-safe secret (32+ characters), then run `python devmemory/mcp_http.py --data ./data --project demo`. The endpoint is http://127.0.0.1:8100/mcp. Configure a native MCP client with Bearer authentication using this secret. Use the same local port through an authenticated SSH tunnel if connecting from another computer; do not expose raw HTTP to a LAN or internet. Host and Origin are checked, explicit project allowlist is mandatory, writes require --allow-write. Legacy protocol revisions 2025-03-26, 2025-06-18 and 2025-11-25; JSON responses, GET returns 405, DELETE ends sessions. Up to 32 sessions with 15 minute idle expiration. No OAuth discovery, SSE streaming, browser clients or modern 2026 protocol support. This independent loopback process remains available; HA uses the managed HTTPS service below. Third-party client and physical HAOS remote acceptance remain pending.

## Managed HTTPS MCP on Home Assistant
Off by default. In the app's own public configuration directory (mounted read-only as /config), install a PEM certificate chain `mcp.crt` and matching unencrypted private key `mcp.key` for the chosen hostname. Protect that directory and its backups; do not use shared Home Assistant credentials. Configure `mcp_enabled: true`, `mcp_token` (independent random URL-safe secret, at least 32 characters), `mcp_projects` (comma-separated project IDs, at most 32), `mcp_host` (client-facing DNS name and port, e.g. devmemory.example.local:8100), and optionally `mcp_allow_write: true`. In Network, explicitly map container port 8100/tcp to the chosen host port (unmapped by default), restart the app. Connect at `https://<mcp_host>/mcp` using Bearer auth and a certificate trusted by the client; never disable certificate verification. Host must match configured authority. A missing or invalid certificate/configuration disables MCP without disabling Ingress. The UI shows listener status, not proof of port mapping, client trust or reachability. Keep access within a trusted LAN/VPN; no public forwarding. No access to other apps' configuration, host networking, Supervisor API or Docker API is requested. Full HA backups may contain tokens and keys; logical JSON backups do not. Physical HAOS acceptance pending.
